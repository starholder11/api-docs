## world_consult_sync

`POST /api/v1/world/{worldId}/consult`

## direct_persona

## world_execute_async

`POST /api/v1/world/{worldId}/execute/async`

**Enqueue an asynchronous world chat turn and get a pollable job.** Uses the same authorization and body as /execute, plus an optional webhookUrl, but returns 202 with an AsyncJobEnvelope. The order of checks is: quota first (429), then the idempotency replay check, webhook validation, and HAM admission. A job record is then written to Redis (24 h TTL), and an internal POST to /api/v1/jobs/\{jobId\}/run starts it; the route answers 202 without waiting for that call and keeps it alive with waitUntil, so the job starts while the client polls. Poll GET /api/v1/jobs/\{jobId\} (pollUrl) for the result. Replays with the same key and payload return the cached 202 envelope.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; platform persona token. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a platform persona token. ## world_stream

**Server-sent events**

Any successful GET; the stream begins immediately and replays buffered events after the resume seq.

| Event | Data |
| --- | --- |
| `<WorldProgramEvent type>` | Each buffered event is sent with SSE event name equal to its type (e.g. ack, obs, content, pee_event, classify, agent_event, skill_select, llm, narrative_trace, traversal_trace, tool_trace, tool, op, delta, receipt, error, done, world_proof, flow_start, flow_complete, flow_failed, node_start, node_complete, node_failed, vsp_asset_load_failure, surface_complete) and SSE id equal to seq. data is the full envelope JSON. ([`WorldProgramEventEnvelope`](/docs/reference/schemas#worldprogrameventenvelope)) |
| `ping` | Heartbeat every 30 seconds. |
| `timeout` | Sent once before close when no terminal event arrived within the idle window. |
| `error` | Stream-side failure (distinct from a buffered error event, which carries the envelope shape). |

**Resume:** Send Last-Event-ID (or ?lastSeq=) with the last seq received; the server replays events with seq greater than it, up to 200 per poll. Replay depends on event-buffer retention.
