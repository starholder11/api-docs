## user_inbox_messages_get

`GET /api/v1/user-inbox/messages`

**List the caller's inbox messages, newest first.** Returns one page of the caller's inbox messages (first-contact requests, room invites, world invites) ordered by createdAt DESC then messageHash DESC, with keyset pagination via an opaque cursor. Archived messages are excluded unless includeArchived=true; sourceKind optionally filters by message kind. Read-only; does not advance the open cursor.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

## user_inbox_archive_post

`POST /api/v1/user-inbox/messages/{messageHash}`

**Archive one of the caller's inbox messages.** Archives the caller's inbox message identified by messageHash (sets archivedAt) and returns the refreshed inbox summary. Ownership is enforced by scoping to the caller; a message that does not exist or belongs to someone else returns 404. ## user_inbox_open_post

`POST /api/v1/user-inbox/open`

**Mark the caller's inbox as opened (advance the seen cursor).** Advances the caller's last-seen cursor to the newest non-archived message, resolved server-side inside one transaction, and updates lastOpenedAt; returns the refreshed summary. The cursor is monotonic (never moves backward), so repeated calls are safe. The body must be valid JSON; topMessageHash is advisory and ignored. When the caller's HAM user mirror row is missing, it is restored from the account's user registry record first; an account with no registry record is created from a signed-in session's sign-in claims, and for an API key it is ERR_ACCOUNT_RECORD_MISSING.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. ## user_inbox_summary_get

`GET /api/v1/user-inbox/summary`

**Get the caller's inbox counters and cursor.** Returns the caller's recipient-global inbox summary: count of non-archived messages, count of messages newer than the caller's last-seen cursor (all visible messages if the inbox was never opened), the newest active message hash/timestamp, and the current last-seen cursor. User-scoped; no world or room parameters. Read-only.
