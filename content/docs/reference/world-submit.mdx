## submission_get

`GET /api/v1/world/{worldId}/submit/{submissionId}`

**Get a submission's lifecycle status.** Returns the public view of a narrative submission in the world: lifecycle status, fulfillment and deferred strategy, linked TextAsset/TextRoot/manifest/bounty ids, rejection details, extraction readiness (with the extraction URL), and status history, plus manifestReady and manifestItemCount from the persisted submission manifest or the linked marketplace bounty manifest. Internal fields (narrativeText, ownerUserId, retryCount, correctionHistory) are omitted. Returns 404 if the submission belongs to a different world. workflow carries the next valid calls and the one blockingReason. Read-only; intended for polling.

## submission_complete

`POST /api/v1/world/{worldId}/submit/{submissionId}/complete`

**Finalize an attended (self_fulfill or post_bounty) submission.** Finalizes a self_fulfill or post_bounty submission whose media has been accepted (status media_fulfilled): settles topology-seed escrow, hands the accepted media to the pipeline and marks media generation complete, then seals the submission as finalized. Takes no request body. Idempotent: an already finalized/registered submission returns 200 with alreadyFinalized=true. Not allowed for platform_default submissions, which the platform finalizes itself. A post_bounty submission whose bounty media the issuer accepts on the bounty review route never reaches media_fulfilled and never needs this call: the platform finalizes and registers it.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session.

## extraction_correction_submit

`POST /api/v1/world/{worldId}/submit/{submissionId}/correction`

**Submit corrections to a submission's extraction.** Records one or more extraction corrections, sets the submission status to correction_requested, appends to its correction history, persists a correction record, and emits an audit event. Re-extraction is queued only if the submission was in awaiting_extraction_review or extraction_complete before the call; otherwise the correction is recorded without re-extraction (see `guidance`). Not idempotent: every call creates a new correctionId and status-history entry. Rejected when the submission is sealed.

## extraction_get

**Approve a submission's extraction and release it to manifest build.** Approves an extraction that is waiting for review (status awaiting_extraction_review or correction_requested): applies any deferred work-strategy request captured at submit time, transitions the submission to extraction_complete, queues the backlot media-generation resume stage, clears the pipeline hold, and emits an audit event. Rejects empty extractions (no entities and no settings). A requested post_bounty that cannot be posted does not fail the approval: when its budget fails the budget rule or the marketplace refuses the post (for example ERR_INSUFFICIENT_FUNDS), the code is recorded in requestedWorkLastError, the strategy stays unselected, and the 200 workflow blocks on strategy_required naming it. A retryable failure is a 500 and nothing is approved. Takes no request body. Not idempotent: a second call returns 409 because the status is no longer approvable.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session.

## fulfillment_get

`GET /api/v1/world/{worldId}/submit/{submissionId}/fulfillment`

**Get media fulfillment status for a submission.** Returns the fulfillment status surface for a submission: strategy, an aggregate status (pending, claimed, submitted, accepted, rejected, generating, failed), per-manifest-item rows with requirement, delivery spec, media URL and rejection reason, the review status, and the import result once media has been accepted. For platform_default the status is pending until extraction completes (and any requested review is approved), generating during media production, accepted once media is done, and failed when generation stalls or the submission is rejected. For post_bounty the state comes from the linked marketplace bounty (marketplaceBountyId): pending while it is open or not yet posted, claimed once a fulfiller claims it (and again after a revision request), submitted while their media set awaits the issuer's review, accepted once the issuer accepts it, and failed if the bounty is cancelled or expires. While submitted, claimId and bountySubmissionId name the set to review on POST /api/v1/world/\{worldId\}/bounties/\{bountyId\}/review; after acceptance fulfilledByUserId names the fulfiller. workflow is the submission workflow view, as on every submission read, and blockingReason repeats workflow.blockingReason so this read names the same blocker. Derived from the submission manifest (or the bounty-linked work manifest), the fulfillment record or linked bounty, and the submission status. Read-only.

## narrative_submit
