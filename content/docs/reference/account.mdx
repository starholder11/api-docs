## account_get

`GET /api/v1/account`

**Get the caller's account profile, credential view, and directory.** Resolves the caller through AuthBoundaryDispatcher (session headers, Bearer/x-api-key API key, or persona token), then authorizes against the account_get registry policy. Returns the owner userId, tenantId, the number of worlds the owner can access, a CallerCredentialView of the presented credential, and a CallerDirectory listing /api/v1 operations that pass credential-level gates for this caller. activeKeyCount is present only for human sessions. Read-only.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session.

## account_api_keys_list

`GET /api/v1/account/api-keys`

**List the signed-in user's API keys.** Authenticates with SessionValidator only, using the middleware-injected x-user-* headers. Lists every API key record the user owns, in any status, sorted by updatedAtMs descending. keyHash is stripped. There is no pagination. The handler never returns an error: an authentication failure or a storage failure both produce 200 with an empty keys array.

## account_api_keys_create

`POST /api/v1/account/api-keys`

**Create an external-agent API key for the signed-in user.** Human session only (SessionValidator). Mints an external_agent API key: keyId key_&lt;16 hex&gt;, actorId agent:&lt;keyId&gt;, status active. Its quotaProfile is copied from the human session. The secret is returned exactly once and stored as a hash. Requested scopes must be a subset of the standard delegable scope list, and requested capabilities must be a subset of the delegable capability set. Every call creates a new key; there is no idempotency.

**Credentials.** Any one of: browser session.

## account_api_keys_rotate

`POST /api/v1/account/api-keys/{keyId}/rotate`
