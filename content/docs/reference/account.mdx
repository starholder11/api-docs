## account_get

`GET /api/v1/account`

**Get the caller's account profile, credential view, and directory.** Resolves the caller through AuthBoundaryDispatcher (session headers, Bearer/x-api-key API key, or persona token), then authorizes against the account_get registry policy. Returns the owner userId, tenantId, worldCount (worlds the owning user owns in the HAM world registry, deleted worlds excluded; not the worlds this credential can read), a CallerCredentialView of the presented credential, and a CallerDirectory listing /api/v1 operations that pass credential-level gates for this caller, plus the published workflows (story.publish, chat.inbox) with each step marked callable for this credential, and roomDirectory: the room-link directory that lists the room operations, which authorize room participants and are not listed here. activeKeyCount is present only for human sessions. Read-only.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

## account_api_keys_list

`GET /api/v1/account/api-keys`

**List the owner's API keys.** Resolves the caller through AuthBoundaryDispatcher (session or API key), then authorizes against the account_api_keys_list registry policy with the caller's own account as the resource owner. Lists every API key record the owner holds, in any status, sorted by updatedAtMs descending; an API key lists all of its owner's keys, itself included. keyHash is stripped. There is no pagination. Read-only.

## account_api_keys_revoke

`POST /api/v1/account/api-keys/{keyId}/revoke`

**Revoke an API key.** A human session or the owner's API key (account:write); a key may revoke any of its owner's keys, including itself, and its request is confirmation-gated. Resolves the caller through AuthBoundaryDispatcher, reads the key under the caller's own account, and authorizes against the account_api_keys_revoke registry policy with that key's owner as the resource owner. Sets the key to status revoked and invalidates its cache. Revoking an already-revoked key returns the same 200 response, so the call is idempotent. The request body is not read.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

**Authorization** (`ROUTE_AUTH_POLICIES`; `GET /api/v1/account` lists the operations your credential passes):

- `account_api_keys_revoke`: callers `human`, `external_agent`; scopes `account:write`; caller must own the resource; mutation class `none`.

**Confirmation.** This operation deletes data. For every request, the first request changes nothing and answers `428` with what it would remove; resending the identical request with `X-Starholder-Confirmation: <confirmationId>` within 5 minutes runs it once. See [Delete confirmation](/docs/authentication#delete-confirmation).
