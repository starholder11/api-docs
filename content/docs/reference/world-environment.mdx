## world_environment_get

`GET /api/v1/world/{worldId}/environment`

**Get the world's Look & Feel selection and its options.** The world's Look & Feel as a selection surface. selection is the current authoring mode (pack, splat or custom) with the values the world renders with. options lists every value a save accepts: packRef, splatRef (mine: the caller's world splats; all: the shared library), backgroundProgram, activeBundle, ambientMode and the meshOpacity range. A value the world already uses but the lists no longer offer is included and labeled (legacy) or Current. fieldsByMode names the selection fields each mode uses. revision is the baseRevision for the next save. Response is marked Cache-Control: no-store.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

- `world_environment_get`: callers `human`, `external_agent`; scopes `world:read`; world policy `externalAgentReadEnabled`: the caller can read the world (checked for `external_agent`); mutation class `none`.

## world_environment_put

`PUT /api/v1/world/{worldId}/environment`

**Save the world's Look & Feel selection.** Saves a Look & Feel selection, the same save the world's Look & Feel editor makes. Send the revision from world_environment_get as baseRevision and a selection with its mode and the fields fieldsByMode lists for that mode; a field the mode uses and the request omits keeps the world's current value, and fields of other modes are ignored. Every value must be one of the published options. Choosing a pack clears custom values; choosing a splat applies the splat shell defaults; choosing custom clears the pack and splat. The save requires the caller to be able to edit the world's environment, and an API key may save only its owner's worlds. Returns the updated surface, whose revision is the next baseRevision.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

**Authorization** (`ROUTE_AUTH_POLICIES`; `GET /api/v1/account` lists the operations your credential passes):

- `world_environment_put`: callers `human`, `external_agent`; scopes `world:write`; world policy `externalAgentAccessEnabled`: the caller owns the world (checked for `external_agent`); mutation class `none`.
