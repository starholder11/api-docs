## mcp_jsonrpc_post

`POST /api/v1/mcp`

**MCP endpoint (protocol 2026-07-28, stateless, JSON responses).** Model Context Protocol server for Starholder: every operation an API key can call is a tool here, generated from this contract (AGENT_EXECUTION_STACK.md §9). Send one JSON-RPC 2.0 request per POST with the credential in X-Api-Key or Authorization: Bearer (an API key or an OAuth access token). There is no initialize handshake and no session: every request carries params._meta with io.modelcontextprotocol/protocolVersion 2026-07-28 and io.modelcontextprotocol/clientCapabilities, and the headers MCP-Protocol-Version (equal to the _meta version), Mcp-Method (equal to method) and, for tools/call, resources/read and prompts/get, Mcp-Name (equal to params.name or params.uri; =?base64?…?= for non-ASCII). Methods: server/discover, tools/list, tools/call, resources/list, resources/templates/list, resources/read, prompts/list, prompts/get. Each tools/call runs the tool's /api/v1 operation with the caller's credential, so a tool can do exactly what that route allows; the route's data is the result's structuredContent, and a route error is an isError result carrying the route's code, message and correlationId. A delete that needs confirmation answers resultType input_required with an elicitation, or returns a confirmationId to send back. Notifications receive 202 with no body. Batches, initialize, GET and DELETE are not supported.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used). A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

**Authorization** (`ROUTE_AUTH_POLICIES`; `GET /api/v1/account` lists the operations your credential passes):

- `mcp_jsonrpc_post`: callers `external_agent`; mutation class `none`.
