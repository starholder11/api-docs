## world_lifecycle_post

`POST /api/v1/world/{worldId}/lifecycle`

**Pause, resume, archive, or delete a world you own.** Owner-only lifecycle transition delegated to the canonical lifecycle service. delete requires the world to be archived first (otherwise 422 lifecycle_precondition_failed) and produces tombstone and sweep report refs. After success the public directory entry is rebuilt or removed, and archive/delete schedule a background billing sync. The idempotency key is deterministic from intent, world, owner, reason and evidenceRefs.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

**Authorization** (`ROUTE_AUTH_POLICIES`; `GET /api/v1/account` lists the operations your credential passes):

- `world_lifecycle_post`: callers `human`, `external_agent`; scopes `world:write`; world role `owner` or higher (humans, and API keys through their owner); mutation class `none`.

**Confirmation.** This operation deletes data. For a request whose body action is 'delete', the first request changes nothing and answers `428` with what it would remove; resending the identical request with `X-Starholder-Confirmation: <confirmationId>` within 5 minutes runs it once. See [Delete confirmation](/docs/authentication#delete-confirmation).
