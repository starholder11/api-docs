## users_search_get

`GET /api/v1/users/search`

**Search the user directory by handle or user space.** Searches the platform user directory for the query (trimmed and lowercased), excluding the caller, and returns ranked candidates plus a resolution verdict (resolved, excluded_self, no_match, or ambiguous). An empty query returns an empty no_match result without searching. Read-only. Search failures are swallowed and reported as an empty no_match result with 200.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

**Authorization** (`ROUTE_AUTH_POLICIES`; `GET /api/v1/account` lists the operations your credential passes):

- `users_search_get`: callers `human`, `external_agent`; scopes `account:read`; mutation class `none`.
