## star_admin_adjust_post

`POST /api/v1/star/admin/adjust`

**Post an admin ledger adjustment (reversal, correction, reclaim, grant).** Requires both the x-star-ledger-token internal secret and an admin human session (SessionValidator plus getRequestUser().isAdmin). **Tip another user STAR with a required memo.** Behaves like /api/v1/star/transfer (authorizeRouteRequest, then the HAM 'star.tip' turn, then the ledger tip, then finalization) but requires a memo. The ledger validates the memo: at most 140 characters, plus a memo policy check. A repeat after success returns 409.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session.

## star_transfer_post

`POST /api/v1/star/transfer`

**Transfer STAR from the caller's wallet to another user.** Authorizes with authorizeRouteRequest (human or external_agent; an external agent spends its owner's wallet). It records the mutation as a HAM turn ('star.transfer') in the sender's default HAM world, runs the ledger peer transfer, and finalizes the HAM turn; a ledger failure tombstones the turn. The recipient's wallet is created automatically if it does not exist. A repeated request with the same idempotencyKey and body after success returns 409, not the original result.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session.

**Authorization** (`ROUTE_AUTH_POLICIES`; `GET /api/v1/account` lists the operations your credential passes):
