## world_bounties_get

`GET /api/v1/world/{worldId}/bounties`

**List bounties in a world, optionally with seeds and gaps.** Returns an offset-paginated list of bounty feed entries for the world, filtered by status, type, suggestedEra and budget range; mine=true restricts the list to bounties where the caller is the issuer or the active claimant. With includeSeeds=true the response also carries the STAR seed feed, and with includeGaps=true it carries the world's published gaps for the caller's surface (agent_readable for an external agent, public_feed otherwise), the same selection and order GET /api/v1/world/\{worldId\}/gaps serves (WORLD_TOPOLOGY_ENGINE §6.4); candidate and internal-only gaps are not included. This GET is not side-effect free: every bounty in the world is lazily normalized on read, which can expire an overdue claim (reopening the bounty) and expire an overdue open bounty (returning its escrowed STAR to the issuer). The response cursor is a stringified offset to pass back as the cursor query parameter, or null on the last page.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

## marketplace_bounty_post

`POST /api/v1/world/{worldId}/bounties`

**Post a new text-story or media-production bounty and escrow its budget.** Creates an open bounty in the world, funds an escrow from the issuer's STAR wallet for the full budget, and records the mutation as a HAM turn under a per-bounty exclusive lock. text_story bounties need objective; when sourceGapId is given the gap's title replaces any client title, the gap description is prepended to the creative brief, and the gap is marked promoted_to_bounty. media_production bounties need sourceTextRootId (a story created by the caller in this world) and creativeBrief, and a work manifest is created. Special case: if the source TextRoot has no submission yet and is media_strategy_pending, the handler skips HAM, writes graph flags and a stub submission, starts the media pipeline, and returns status 'deferred' with bountyId null. With idempotencyKey the bountyId is a hash of the key alone; a retry of an already-admitted request is rejected by HAM (422) rather than replayed.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

## marketplace_bounty_cancel_or_reopen

`POST /api/v1/world/{worldId}/bounties/{bountyId}`

**Cancel an open bounty and return its escrow, or reopen a bounty (body action selects which).** One POST with two branches. The handler validates body.action before authentication, then authorizes against the policy the action names: action cancel against marketplace_bounty_cancel, action reopen against marketplace_bounty_reopen (both scope bounty:post and canAccessBounties). Only the issuer or the world owner may call either. cancel: allowed only while the bounty is open (an already-cancelled bounty is a no-op in the flow). It releases any active claim, resets a promoted source gap to marketplaceStatus none, returns the escrowed budget to the issuer (data.settlementRefs names the escrow return receipt), and answers status cancelled. reopen: allowed from claimed, submitted, under_review, revision_requested, expired, and rejected; active-claim fields are cleared and the bounty answers status open. A cancelled or registered bounty is terminal (409 ERR_BOUNTY_TERMINAL), and accepted, finalized, or already-open bounties cannot be reopened (409 ERR_INVALID_BOUNTY_TRANSITION). **Accept, reject, or request revision on a bounty submission.** The issuer decides on the current submission. accept triggers automatic finalization and escrow release to the claimant, so the resulting status is finalized or registered; reject releases the claim and returns the bounty to open; revision_requested (alias request_revision) moves to revision_requested, or to open once maxRevisions is exceeded. feedback is required for non-accept decisions. For a story's media bounty (post_bounty), accept also resumes the story's pipeline: the narrative submission moves to media_generating and then registered, with no complete call. The decision is recorded as a HAM turn under a per-bounty lock; if auto-finalization or apply fails after the decision commits, the call returns 502 even though the decision stands.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

## marketplace_bounty_settle

`POST /api/v1/world/{worldId}/bounties/{bountyId}/settle`

**Complete settlement of a finalized bounty and mark it registered.** Issuer-only operation, by session or by the issuer's API key, for a bounty in finalized or registered state: retries the escrow release to the claimant, applies any media top-up and downstream cascade, and moves finalized to registered. Intended as the completion/retry path after acceptance; calling it on an already registered bounty re-runs the idempotent ledger steps. Recorded as a HAM turn under a per-bounty lock.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. ## marketplace_bounty_staging_upload

`POST /api/v1/world/{worldId}/bounties/{bountyId}/staging/upload-url`

**Get a presigned S3 PUT URL to stage one media item for a bounty.** For the active claimant of a media_production bounty, validates the target slot and file metadata and returns a presigned S3 PUT URL (valid 900 seconds) plus the staging session id to reference later in submit. Images must be png/jpeg/webp up to 25 MB and videos mp4/webm up to 400 MB, with a file extension matching the content type; the PUT must send the same Content-Type. The call is recorded as a HAM turn; each call issues a fresh upload URL.

**Credentials.** Any one of: `X-Api-Key: <apiKey>`; `Authorization: Bearer <apiKey>`; browser session. Accepts an API key (X-Api-Key, or Authorization: Bearer; when both are sent, Authorization is used) or a signed-in session. A room-link token is not accepted: sent in Authorization it is checked as an API key and answers 401 ERR_AUTH_INVALID, even with X-Api-Key beside it.

**Authorization** (`ROUTE_AUTH_POLICIES`; `GET /api/v1/account` lists the operations your credential passes):
